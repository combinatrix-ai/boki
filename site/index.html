Financial models as code. Banker-grade Excel as output.

Write the business in Python. boki books the double entries and builds a three-statement model in your accounting standard, where every cell in the workbook is a live formula.

Get started Read the docs uv add "boki[excel]"
plan.pyimport boki as b from boki.lib import compound from boki.units import USD, year m = b.Model("Widget Co", start="2027-01", periods=5, step=year) co = m.entity("Widget Co", standard=b.USGAAP, currency=USD) co.bs.opening(cash=20e6 * USD) growth = m.input("Revenue growth", 0.25) sales = co.pl.revenue("Product sales", compound(40e6 * USD, growth)) co.pl.cogs("Cost of sales", 0.45 * sales) co.pl.sga("Operating expenses", 6e6 * USD + 0.15 * sales) co.bs.fixed_asset("Plant", 30e6 * USD, at=0, life=10 * year) co.bs.loan("Term loan", draw={0: 25e6 * USD}, rate=0.07, repay=5e6 * USD) co.pl.income_tax("Income taxes", rate=0.21, base=co.pl.pretax_income) m.render().to_excel("widget.xlsx", money="$mm")

Why boki

The model stays in code. Excel is what it produces.

Spreadsheet models cannot be diffed, tested or reviewed, and their hardest parts — circular references, values pasted by a macro — are the least visible. boki keeps the logic where it can be read, and hands analysts a workbook they can audit cell by cell.

Every number is a live formula

Statements link to a Model sheet with one row per line and one column per period. Change an input and watch it flow through. Every formula is recalculated by an independent engine and compared with boki.

The accounting is done for you

Write revenue, costs, payment terms, assets and loans. boki writes the journal entries, depreciation, interest and all three statements.

co.pl.revenue("Sales", 120 * USD,
              settle=b.delay(1))

Mistakes cannot get through

Units are types. The balance sheet is a view of one ledger, so it cannot be unbalanced. Sanity checks run in every period.

UnitError: cannot add 100,000 USD
           and Capacity (kW)

The hard parts are explicit

Debt sculpting, interest during construction and goal seeks are solved with m.solve, named in the model. Any other loop stops with the cycle it found.

CycleError: Debt -> Interest during
  construction -> Debt (in 2027)

It is just code

Diff it, review it, test it. Stamp out one model per site, run scenarios in a loop, and pin the numbers someone signed off on.

b.expect(m.render(),
  {co.pl.net_income: [7.9e6, 7.3e6]})

Agent-friendly

An AI agent can write and change a model like any other code — and the unit, ledger and sanity checks catch the mistakes it makes.

One model, every presentation

Your standard's statements, in your house style.

The same model prints in the line order and names of US GAAP, IFRS or J-GAAP, by period or fiscal year, and exports in a banker, 10-K, Japanese or plain style.

US GAAPStatement of operations and a current-first balance sheet
IFRSStatement of profit or loss, non-current-first statement of financial position
J-GAAPOrdinary income, and goodwill amortized in the consolidated books
Investment-banking grade

3-Statement, LBO and DCF workbooks — all live formulas.

Combine historical actuals (actual_until), proof-carrying Excel formula rewrites (b.block), live scenario switching (=INDEX), summary panels (b.panel), and 2D sensitivity tables (b.sensitivity) whose axis headers recalculate directly in Excel.

3-Statement Model

3Y historical actuals (2022A–2024A) + 5Y forecast (2025E–2029E), US GAAP, indirect CF, and Valuation & Credit Bridge.

LBO Model

Live Sources & Uses, Goodwill, Pro Forma Opening BS, 2-tranche Debt Waterfall + 100% Excess Cash Sweep, and Sponsor IRR/MoIC.

DCF Valuation

CAPM WACC, mid-year discounted UFCF, Perpetuity Growth & Exit Multiple bridges, and live 2D sensitivity matrices.
Proof

Built by rewriting real models, line by line.

boki was developed by recreating public financial models and comparing every result with the source workbook. Along the way it found places where the originals disagree with themselves.

  2. Create a model and an entity with an accounting standard.
  3. Add revenue, costs, an asset and a loan.
  4. Render, read the statements, and export to Excel.
